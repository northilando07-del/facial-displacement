# 88：先精修脸部大形，再细分细节

默认入口仍是 `start_webui.bat`，配置为 `displacement.json`，页面地址为 `http://127.0.0.1:7861`。当前仓库整理阶段已通过纯 Python 单元测试；完整模型生成、Blender 烘焙和视觉验收仍需要本地真实资产与外部环境。

## 阶段顺序

| 阶段 | 精度 | 处理内容 |
| --- | --- | --- |
| 粗读取一 | 每组最多16个原始网格面 | 多光源低频法线、脸部轮廓对应点、五官位置，求平滑三维形变 |
| 粗读取二 | 每组最多4个原始网格面 | 重新投影已修改的模型，更新光照与法线误差，继续精修五官体块 |
| 初始网格 | 1格原始网格精度 | 在精修基础模型上重新进行 FULL 提取，求解剩余法向位移 |
| 细节 | 默认4级自适应细分 | 继承已有形变，每层仅求剩余误差；保留原有细分预算与置信度限制 |
| 输出 | 8192×8192 | 总向量位移、细节灰度位移、各层增量、最终高模烘焙法线 |

16格指原始 OBJ 的16个面，不是16×16像素，也不是16×16个面。计算时按拓扑连通性分组；区域末尾或小的独立区域可能不足16/4个面。粗层不合并网格，保留原始顶点编号、三角面对应、UV与SOAP重心坐标。

每组共同求解XYZ系数；分组权重在共享顶点上扩散，邻区共用连续位移，并加入网格拉普拉斯平滑。每个粗层默认迭代3次，每次都用当前几何重新投影、重新估计全局光照，再求剩余法线/对应点误差。粗层允许三维运动，之后的细节限制为法向位移。

## 大形约束与参数

输入至少三张同一人物、同一视角和表情、不同主光方向的图。沿用现有FAN/SOAP自动绑定。三图先通过68点做全局相似配准；光照使用全局方向光估计，联合解法线与共享反照率项，过滤高光、阴影、配准不可靠区域。低通作用于求得的法线残差，避免直接把绝对明度当高度。

当前轮廓约束使用17个下颌轮廓对应点，五官约束使用其余对应点；没有额外输入侧面轮廓、实测深度或解剖部件控制器。光源方向也是估计值，不是标定值。局部光源退化时法线权重会降低或归零，对应点约束仍可调整投影结构。这不等于从任意三张图片都能准确恢复真实三维形状。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `structure.cells` | `[16, 4]` | 两层粗读取顺序 |
| `structure.iterations_per_stage` | `3` | 每个粗层更新投影与求解的次数 |
| `structure.maximum_displacement_mm` | `4.0` | 相对原始模型的大形位移长度上限 |
| `structure.step_limits_mm` | `[3.0, 1.5]` | 两层单次迭代步长上限 |
| `structure.normal_angle_degrees` | `25` | 粗层候选法线角度限制 |
| `structure.analysis_max_side` | `1024` | 粗层低频分析尺寸；不限制最终贴图尺寸 |
| `displacement.levels` | `4` | 1格基础精度之后的细分次数上限 |
| `displacement.maximum_displacement_mm` | `1.5` | 大形校正后的细节法向位移上限 |
| `texture_resolution` / `bake_resolution` | `8192` / `8192` | 贴图尺寸，UI联动保存 |

若原始模型没有指定毫米单位，按原始SOAP两侧脸宽估算140 mm，并将这一比例固定到全部阶段。粗层通过统一缩小步长保持场的平滑，并检查局部面翻转与面积收缩；这不是完整的全局自相交或解剖正确性检测。

细分仍是共边的线性三角细分，不是Catmull–Clark。信号不足或达到几何预算时可提前停止；运行报告会记录实际完成级数。未受支持的毛孔不会凭空合成。

## 输出与使用

默认结果目录：`output/document88_8k_level4`。修改前源码与配置保存在 `backup/before_document88_20260914_223401`；此前77版结果保留。

- `structure/original.obj`：计算时保存的原始形状。
- `structure/coarse_16.obj`、`structure/coarse_04.obj`：两层粗读取后的真实网格。
- `structure/report.json`：粗层支持范围、全局光照估计、迭代误差与实际位移。
- `levels/level_00.obj`：1格精度的残差解；`level_01`至`level_04`为实际完成的细分层。
- `head_displaced.obj`：最终高模；相应NPZ同时保存原始参考位置、大形位置、总XYZ位移和细节高度。
- `maps/<材质>/vector_displacement_16.png`：总形变，16位RGB，原始OBJ坐标轴中的XYZ，8192×8192。
- `maps/<材质>/vector_displacement_mm.npy`：同一总XYZ位移的float32毫米数据。
- `maps/<材质>/vector_displacement_decode.json`：坐标系、零点、量程与单位换算说明。
- `maps/<材质>/displacement_16.png`：相对4格精修基础模型的细节法向位移，16位灰度，8192×8192。
- `maps/<材质>/normal_opengl16.png`：从最终高模烘焙回原始低模的切线法线，16位RGB，8192×8192。
- `layer_maps/coarse_16`、`layer_maps/coarse_04`：两层粗读取的XYZ增量；`layer_maps/level_*`是每层细节高度增量。
- `scene/displacement88.blend`：原始模型、大形校正模型、最终高模和烘焙法线对照；`scene/*_comparison.png`为三种视角的四列对照。

总向量图设为Raw/Non-Color；XYZ零点都是0.5。解码为原始模型单位：

```text
D = (RGB - 0.5) * (2 * range_mm) / millimeters_per_unit
```

将总向量图用于具有匹配UV和线性细分的原始低模。灰度细节图用于 `coarse_04.obj`。不要在已精修的模型上再次叠加总向量图；它已经包含大形和细节。总向量图使用物体空间，不能当切线法线图直接连接。

8K总向量图使用磁盘映射的float32缓冲及逐行PNG编码；中间FULL提取只保留分析证据，不重复烘焙无用的各层8K法线。8K代表输出采样尺寸，不表示低分辨率参考图增加了真实细节。

## 本地运行

关闭旧UI服务后双击 `start_webui.bat`，在新页面确认“16格 → 4格 → 1格 → 4级细分”和8K，再点击生成。打开页面本身不会启动任务。

```powershell
python run_displacement.py --config displacement.json
```

`--geometry-only`只生成大形与细分模型；`--rebuild-evidence`强制重新提取细节证据。大形校正始终重新执行，之后才校验是否能复用对应的细节证据。默认生成流程不自动运行旧77版测试/验证脚本；运行报告与测试报告分开理解。

单元测试不等于端到端视觉验收。真实资产上的模型生成、Blender 烘焙和最终视觉质量仍应通过 UI/命令行完整跑一次后人工检查。
